Research Question & Motivation

Retailers must decide inventory replenishment levels four weeks before demand is observed. The central empirical question is: How much do historical sales, calendar information, and selling price features improve 28-day-ahead retail demand forecasts over simple baselines?


Using a stratified subset of 1,000 item-store series (1,525,319 observations) from Walmart stores across California, Texas, and Wisconsin, we evaluate direct 28-day forecasting methods under chronological validation splits.

Headline Findings
  • Lagged Sales Dominate: Nearly all predictive lift comes from historical sales lags. Adding calendar variables gives a small secondary boost, while price features add virtually zero incremental gain once historical sales are present.
  • ML Models Beat Baselines: Both Ridge regression and Gradient Boosted Trees (GBT) outperform the strongest baseline (4-week same-weekday mean) by 3.6% in MAE and ~8% in RMSE on held-out test data.
  • Statistical Tie: Boosted Trees and Ridge regression are statistically tied (MAE difference -0.0011, 95% bootstrap confidence interval [-0.0105, 0.0083]).
  • Zero-Inflation Mismatch: ML models trained under squared-error loss beat baselines on fast-moving products and positive sales days, but lose to simple baselines on zero-sales days and slow-moving items (<0.25 units/day).

Data Preprocessing & Quality Checks
  • Pre-launch Filtering: Every product series contains consecutive leading zeros prior to its first price record. These 21.4% pre-launch rows were removed so model fitting reflects active product availability.
  • Zero Negatives: Unit sales contain no negative values.
  • Missing Events: Missing event names in `calendar.csv` were originally parsed as empty strings rather than nulls, creating constant indicator columns; this was identified and remediated prior to final model runs.
  • Chronological Data Leakage Shielding: Transformations (standardization means/variances, volume tiers) were fit strictly on training rows ($d \le 1885$).

04 — Feature Engineering Laboratory

Constructing Direct 28-Day Features Without Iterative Leakage

Direct 28-Day Forecasting Formulation

To forecast a 28-day window ($t = T+1, \dots, T+28$) without recursive error propagation, all features for target day $t$ use only observations available at or before origin day $T$. Thus, lag $\ell$ is defined as $\ell \ge 28$.

Feature Groups (47 Features Total)
  • History Features (6): Lags $y_{i, t-28}, y_{i, t-35}, y_{i, t-42}, y_{i, t-56}$, plus 7-day and 28-day rolling means ending at $t-28$.
  • Calendar Features (26): Day-of-week indicators, month indicators, SNAP food assistance state flags, and event indicators.
  • Price Features (2): Weekly selling price and selling price ratio relative to 28 days prior ($P_t / P_{t-28}$).
  • Static Categorical (13): One-hot encodings for Store ID and Category ID (FOODS, HOBBIES, HOUSEHOLD).
Preventing Data Leakage
# Direct 28-Day Feature Calculation Rule
def build_direct_features(df, origin_day):
    # Lags must be at least 28 days back from target day t
    df['lag_28'] = df.groupby('id')['sales'].shift(28)
    df['lag_35'] = df.groupby('id')['sales'].shift(35)
    df['rolling_mean_7'] = df.groupby('id')['lag_28'].transform(
        lambda x: x.rolling(7).mean()
    )
    # Standardization fit strictly on training set
    scaler.fit(df[df['day'] <= 1885][feature_cols])
    return df
